## 9. Reporting contract

Sections 1-8 describe state and procedure; this section defines what a report
must contain. It is mandatory for the next session.

### 9.1 After every promotion — compact receipt

1. **Entry and evidence** — `pattern_id`, reviewed HEAD, `owner_page_sha256`,
   `card_sha256`, report path and report SHA-256, verdict and minor count.
2. **Coverage** — technical/decision sufficient, owner-accepted, remaining, and
   the current 4/4..0/4 tier counts.
3. **Timing** — the new promotion-to-promotion interval, total entries, mean and
   range; state that the basis is commit intervals including reviewer and
   integration wait, not a stopwatch.
4. **Charts** — paths to both regenerated SVGs; confirm the new entry is visible,
   all promoted entries are present, and the forecast count is dynamic.
5. **Forecast** — optimistic/base/pessimistic days and the tier rates used.
6. **Verification** — exact commands and results. Distinguish a full suite run
   from targeted tests. Never write “CI passed”.
7. **Limits** — owner acceptance is not implied; list any pending gate.

### 9.2 At batch end — full report

Include everything above, plus:

- full-suite result and duration, or an explicit statement that it was not run;
- validator list and results;
- changed artifacts and hashes;
- remaining count derived from `owner-units.v1.json`, never hard-coded;
- open review/promotion/acceptance gates and the next concrete action.

A routine intermediate status report is not required. Report after a promotion,
at a batch boundary, or when a real blocker needs owner input.

### 9.3 Charts are part of the report

After **every** promotion, regenerate:

- `authoring/promotion-entry-timing-2026-10-29.svg`;
- `authoring/promotion-forecast-2026-10-30.svg`.

Both charts must include **all** promoted entries, not a recent window. The
single-entry chart must show the just-promoted entry and keep x-axis labels
readable (currently rotated -45°). The forecast must be recomputed from the full
timing set and `owner-units.v1.json`; its title and remaining count must not be
hard-coded. Report both paths in the same message as the promotion.

### 9.4 Review reports

External review reports are raw evidence, not summaries:

- save the reviewer's verbatim JSON/body under `authoring/ai-reviews/`;
- add one index row with the report SHA-256;
- record reviewer harness, HEAD, scope, verdict, findings and limits;
- update the index count guard (currently **121** reports in
  `tests/test_tycho_ai_reviews.py`);
- never present a review as owner acceptance, CI or sufficient coverage by itself.

### 9.5 Rule numbering

Timing bookkeeping is rule 36 on this feature branch and rule 37 on `main`
(where rule 36 is the index/search read-only rule). Goal-per-task is rule 37 on
this branch and rule 38 on `main`. Cite the rule by content, not only by number.
